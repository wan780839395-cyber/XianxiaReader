# 变更与排障流程

2026-10-19 用户要求将本轮教训纳入整个项目；本文件由根AGENTS.md引用，适用于后续所有会话。当前状态以PROJECT_STATUS.md、HANDOFF.md和实际验证记录为准。

## 每个切片的工作合同

开始实现前，在HANDOFF中写明本次目的、触及文件/职责、必须保留的行为与最小验证。先使用现有模块边界，参考适用版本的官方文档和成熟实现；记录采用的边界与版本差异。不要同时提取字体、位置、设置和会话，不顺便升级引擎或重做界面。

定向验证通过后冻结源码，再完成最终发布门槛。测试的用例耗时与准备、编译、导出成本分开记录；不要为每个小编辑反复打包。组件复用必须核原始完整日志、精确源码/配置、SDK及设备环境，并明确报告分项来源，不能拼成一次全套绿灯。任一发布门槛失败都不得生成“已验收”IPA。

把预检与完整验证放在同一job前，先按实际runner分别估算准备、编译、定向、完整测试、录屏/附件导出、设备Release及artifact上传的总耗时，预留收集失败证据的时间。换主机后不能沿用旧主机的耗时假设；同机复用构建目录也不能当作完整测试免费。超时后先核实际已完成与未完成阶段，再决定重跑范围，不把流水线预算不足说成源码失败。

## 每次失败的决策

1. 保留真实退出码、完整日志、summary和必要原生证据，确认失败发生在哪个阶段；先核实际文件、任务和输入，不以聊天或可见日志尾部代替。
2. 写出假设与反例。明确下一次最小实验要区分哪些原因；只有新改动、新条件或新增诊断能够检验假设时才重测。
3. 区分本片行为失败、其他边界失败和尚未确认的运行条件。其他失败可以阻塞发布，但不自动扩大本片生产代码修改范围；不得无证据宣称与本片无关或全是环境问题。
4. 同类失败反复出现却没有新证据，停止盲跑整套，改做最小对照。禁止以加重试、放宽预算、删断言或随机修改多个层次换绿灯；偶然重放通过只证明该次通过。
5. 验证修正后先重跑直接受影响范围，结果支持假设后再扩大到必要回归和发布门槛。任务与代码、测试同样需要隔离。

测试在setup/teardown中恢复设备方向、App进程、窗口与任务；失败不能把共享状态留给下一例。检查生命周期与异步取消是否真正完成，不能只依赖可能被中止跳过的局部defer。

联合断言失败时，先分项记录字体就绪、目标字可见等独立条件及必要几何信息，避免一条超时被直接解释成位置丢失。跨栏长段的整体矩形不代表某个字可见，需用该字的Range核对。断言之后的诊断不是与此前判定原子同步，不能把稍后观察倒写成失败当时的状态。

每轮冻结证明使用独立文件名，消费证明前校验sourceRevision、实际Git blob和文件摘要；数量相同或文件存在不代表证据对应当前版本。写错文件名时保留实际原件与纠正记录，不能覆盖历史证明后继续引用旧含义。
